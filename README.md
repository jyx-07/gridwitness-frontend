# GridWitness Frontend

전력 고장파형 분석 지원 시스템 GridWitness의 웹 화면 (React + TypeScript + Recharts + three.js).
FastAPI 서버(`https://gridwitness-api.https.gsmsv.site`)에 연결되어 등록·입력 진단·분석·검토 기록을 남깁니다. 서버 주소는 설정에서 바꿀 수 있습니다. 사건 목록은 서버(`GET /incidents`)에서 불러오고, 원본 파형은 등록한 브라우저에만 보관합니다.

```bash
npm install
npm run dev          # http://localhost:5173
```

## 데이터와 AI 분리

세 데이터는 단위·측정 주기·설비 규모·목적이 달라 하나의 모델에 함께 학습시키지 않습니다.

| 데이터 | 분석 대상 | 사용처 |
|---|---|---|
| Arduino + INA219 ×1 (Mock 또는 실측) | 모형 전체의 5V DC 전압·전류 | **IoT 이상 탐지** — `src/lib/village.ts` `anomalyScore()` |
| 공개 고장파형 (Xiong et al.) | 교류 고장 이벤트 7채널 | **고장파형 4종 분류** — `src/api/mock.ts` `runAnalysis` |
| 한전 전력사용량 공공데이터 | 지역·시간대별 소비 패턴 | 패턴 분석·비교, 마을 부하 시나리오 (학습 미사용) |

IoT 이벤트를 사건으로 등록하면 DC 계측 기록 그대로 `IotCase`가 됩니다. 교류 파형으로 바꾸지 않습니다.

## 예시 데이터와 시나리오

- 처음 열면 **[예시] 사건 8건**이 실제와 같은 처리 과정(등록 → 진단 → 분석 → 검토)을 거쳐 만들어집니다: 분석·검토 완료, 판단 보류, 60Hz COMTRADE 범위 밖, 입력 거부, 원인 추정 요청 보류, IoT LED 단선(검토 완료)·전압 강하·릴레이 고착. 설정 → 사건 데이터에서 예시로 되돌리거나 모두 비울 수 있습니다 (`src/api/seed.ts`).
- 고장파형 등록 화면의 **예시 시나리오 15종** (`src/lib/scenarios.ts`): 1상 지락·순간 이상·2상/3상 단락·헤더 없음 / 샘플링·길이·60Hz 범위 밖 / 결측·채널 순서·빈 파일 / COMTRADE 60Hz·BINARY·In 없음·전압 채널 없음. 각 시나리오에 기대 판정이 붙어 있습니다.
- 스마트 마을 고장 시뮬레이션: LED 단선, 누설·과전류, 어댑터 전압 강하, 전원 상실, **릴레이 접점 고착**, **통신 끊김**.

## 목 데이터 주의

- 고장파형 분류 점수는 파일 해시로 만든 가짜 값입니다.
- 공공데이터 화면의 기본값은 **예시 데이터**(실제 한전 수치 아님)입니다. `CSV 양식 받기`로 형식을 확인하고,
  공공데이터포털·한전 전력데이터 개방포털에서 받은 CSV를 열 이름 `지역,계약종별,월,요일구분,시간,사용량`에 맞춰 가져오면 그 값으로 바뀝니다.
- 스마트 마을 계측값은 실측 장치를 연결하지 않으면 Mock 시뮬레이터 값입니다 (`arduino-sim-01`). 사이드바 하단에 출처가 표시됩니다.
- 공공데이터 패턴의 마을 재생은 채널 릴레이로 LED를 하나씩 켜고 끄는 방식이라, 채널 상태를 보고하는 장치(또는 시뮬레이터)에서만 동작합니다.

## 실제 모형 연결 (선택)

회로는 채널 릴레이 구성 기준입니다.

```
5V DC 어댑터 → 전체 릴레이 (Arduino D2, COM→NC, 마을 전체 ON/OFF)
  → INA219 ① 0x40 (주택 구간) → 채널 릴레이 ①②③ (D3·D4·D5, COM→NO) → 주택 1~3 LED
  → INA219 ② 0x41 (가로등 구간) → 채널 릴레이 ④⑤ (D6·D7, COM→NO)   → 가로등 1~2 LED
INA219 두 개: A4(SDA) · A5(SCL) 공통 (INA219 ① → ②로 이어서 연결)
빵판: Arduino 5V → + 레일, GND·어댑터 − → − 레일. 모든 모듈의 VCC/GND와 LED의 − 선이 이 레일에서 나뉨
```

- 측정은 INA219 두 개로 **구간(주택·가로등)** 전압·전류를 따로 잽니다. LED 하나하나의 전류는 재지 않으므로, 구간 전류로 켜진 개수를 추정하고 어느 LED인지는 **채널 점검**(채널을 하나씩 꺼서 구간 전류 변화를 봄)으로 확인합니다.
- 제어는 전체 릴레이로 마을 정전·복구, 채널 릴레이로 **LED 하나씩 끄기·켜기**가 됩니다.

Chrome·Edge에서 **설정 → 실측 장치**를 누르면 Web Serial로 모형과 통신합니다. 연결하지 않으면 Mock 시뮬레이터로 같은 화면이 동작합니다.
프로토콜(115200 baud, 줄 단위):

```
장치 → 웹 (0.5초마다)  {"v":5.02,"i":0.281,"relay":1,"ch":[1,1,1,1,1],"vh":5.02,"ih":0.168,"vl":5.01,"il":0.113}
                       v·i 마을 전체, relay 마을 전원, ch 채널 1~5, vh·ih 주택 구간, vl·il 가로등 구간
웹 → 장치              RELAY 0 / RELAY 1      마을 전체 정전 / 복구
                       CH <1~5> <0|1>         채널 하나 끄기 / 켜기 (예: CH 3 0)
```

`ch`와 구간 값이 없는 예전 스케치({"v","i","relay"}만)도 계속 받지만, 이때 채널 제어와 채널 점검은 잠깁니다.
부품·핀·배선 데이터는 `src/lib/hardware.ts` 한 곳에 있고, 3D 지하 배선과 설정의 배선표가 함께 씁니다. 배선 색은 도면의 색상 규칙(빨강 5V, 검정 GND, 초록 D2~D7, 파랑 SDA, 노랑 SCL, 주황 LED+, 회색 LED−)을 따릅니다.
예제 스케치: `arduino/gridwitness_village/gridwitness_village.ino` (Adafruit INA219 라이브러리). 스케치 위쪽의 `MASTER_USES_NC`·`CH_USES_NC`(릴레이 접점을 NC/NO 중 어디에 연결했는지)와 `RELAY_ACTIVE_LOW`(모듈이 LOW에서 동작하는지)를 배선에 맞게 바꿉니다.

## 3D 성능

기본 모드는 30fps·낮은 해상도·정적 그림자·후처리 없음으로 동작하고, 화면 밖이거나 탭이 숨겨지면 렌더링을 멈춥니다. 마을 화면의 **고화질** 버튼을 켜면 AO·블룸 후처리와 60fps를 씁니다.

## 분석 서버 연결

- 구현: `src/api/backend.ts` (인터페이스는 `src/api/index.ts`의 `GridWitnessApi`, 모드·주소·상태는 `src/lib/backend.ts`). 빌드 때 `VITE_API_BASE=<주소>`로 기본 주소를 바꿀 수 있습니다.
- 사용하는 엔드포인트: `POST /incidents`, `POST /incidents/{id}/validation`, `POST /incidents/{id}/analysis`, `POST /incidents/{id}/reviews`, `GET /incidents/{id}/audit`, `POST /energy/iot/summary`, `GET /energy/kepco/usage`(공공데이터 화면).
- 사건 목록은 `GET /incidents`로 받습니다. 서버에 원본·진단·분석 결과를 다시 받는 API가 없어, 파형과 진단 상세는 등록한 브라우저(`gridwitness.cases.backend.v1`)에만 있고 다른 브라우저에서는 목록·이력·검토만 보입니다.
- 서버에 분석 모델이 연결되어 있지 않아(`MODEL_NOT_CONFIGURED`) 이벤트 유형은 항상 '판단 보류'이고 특징값만 표시됩니다. 서버가 `classification`을 내려주기 시작하면 화면이 결과를 표시하도록 대비해 두었지만 그 응답 모양은 확인하지 못했습니다.
- CORS는 서버에서 `https://jyx-07.github.io`와 `http://localhost:5173`만 허용합니다.
